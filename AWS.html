01

IAM

MCP Verified

Identity & Access Management — siapa boleh ngapain di AWS lo. Ini pondasi keamanan; salah di sini = pintu terbuka buat penyerang.

Konsep Inti

Root userPemilik akun, kekuasaan penuh tanpa batas.▶
Identity default saat akun dibuat. Sesuai AWS best practice: jarang dipakai, amankan dengan MFA & password kuat, dan jangan bikin access key untuk root. Buat daily work, pakai identity lain.
IAM userIdentity per orang/aplikasi.▶
Untuk login console / akses programatik. Tapi AWS sekarang merekomendasikan temporary credentials lewat role ketimbang long-term access key kalau bisa.
IAM groupKumpulan user dengan izin sama.▶
Daripada attach policy ke tiap user satu-satu, masukkan user ke group (mis. developers), lalu attach policy ke group. Lebih rapi & scalable.
IAM roleIdentity sementara untuk service/akses.▶
Tidak punya password/key permanen — memberikan temporary credentials. Dipakai untuk service-to-service: mis. EC2 pakai role buat akses S3 tanpa nyimpan key. Inilah cara aman.
IAM policyDokumen JSON aturan izin (Allow/Deny).▶
Menentukan Action apa boleh ke Resource mana. Prinsip wajib: least privilege — kasih izin seminimal yang dibutuhkan, bukan "*".
MFALapisan login kedua (kode dari HP).▶
Multi-Factor Authentication. Aktifkan terutama di root & user admin. Walau password bocor, penyerang tetap keblok.
🎯Real Case"DevOps butuh akses deploy ke EC2 & S3 — harus pakai root?" → Tidak. Buat IAM user (atau lebih baik, gunakan role/SSO), masukkan ke group, attach policy yang cuma mengizinkan akses EC2 & S3 yang relevan, lalu aktifkan MFA. Root disimpan, jangan dipakai harian.
⚠️Common MistakePakai root buat kerja harian · share access key antar orang · policy terlalu wildcard (Action:"*", Resource:"*"). Tiga ini temuan audit keamanan paling sering.
🧠DevOps MindsetMulai dari izin kosong, tambah pelan-pelan saat dibutuhkan (least privilege). Jauh lebih aman daripada kasih akses penuh lalu "nanti dirapiin" — yang nggak pernah kejadian.
02

VPC

MCP Verified

Virtual Private Cloud — jaringan privat lo di AWS. Semua EC2, RDS, dll "tinggal" di dalam VPC. Ini "gedung" di mental model tadi.

Komponen Penting

Region & AZLokasi fisik data center.▶
Region = wilayah geografis (mis. ap-southeast-1 Singapore). Availability Zone (AZ) = data center terpisah dalam region. Sebar resource ke beberapa AZ = tahan kalau satu AZ down.
CIDRRentang IP privat VPC.▶
Mis. 10.0.0.0/16 = ~65k IP. Subnet ngambil potongan dari sini, mis. 10.0.1.0/24.
Public subnetBisa terhubung ke internet.▶
Subnet yang route table-nya mengarah ke Internet Gateway. Cocok untuk web server / Load Balancer yang harus diakses publik.
Private subnetTertutup dari internet langsung.▶
Tidak punya route langsung ke Internet Gateway. Cocok untuk database (RDS) & backend yang tak boleh diakses publik.
Route TableAturan "ke sana lewat mana".▶
Menentukan tujuan traffic. Public subnet punya route 0.0.0.0/0 → Internet Gateway.
Internet Gateway (IGW)Pintu gerbang ke internet.▶
Komponen yang memungkinkan VPC berkomunikasi dengan internet. Tanpa IGW + route, tidak ada akses publik.
NAT GatewayPrivate subnet keluar ke internet (1 arah).▶
Biar EC2 di private subnet bisa download update ke internet, tapi tetap tak bisa diakses dari luar. Hati-hati: NAT Gateway kena biaya per jam + per GB — bisa mahal untuk lab pemula.
🎯Real Case"Kenapa EC2 di private subnet nggak bisa diakses langsung dari internet?" → Karena route table private subnet tidak mengarah ke Internet Gateway, dan instance-nya tak punya public IP. Itu memang disengaja demi keamanan — backend & database harus tersembunyi.
🧠DevOps MindsetPola standar production: Load Balancer di public subnet, aplikasi & database di private subnet. Yang menghadap internet sesedikit mungkin.
03

Security Group & NACL

MCP Verified

Dua lapis firewall di VPC. Paham bedanya = bisa debug "kenapa nggak bisa connect" dengan cepat.

Security Group · level INSTANCEStateful. Menempel di EC2/resource. Cuma punya allow rule (implicit deny sisanya). Karena stateful, kalau inbound diizinkan, traffic balasannya otomatis diizinkan — nggak perlu atur outbound-nya.
NACL · level SUBNETStateless. Menempel di subnet. Punya allow & deny rule (bisa blok IP spesifik). Karena stateless, lo harus atur inbound DAN outbound secara eksplisit (termasuk port balasan/ephemeral).

Port yang Wajib Hafal

22SSH — remote login ke server.▶
Batasi hanya ke IP lo (mis. 1.2.3.4/32), jangan ke seluruh dunia.
80HTTP — web traffic biasa.▶
Boleh dibuka ke publik (0.0.0.0/0) kalau memang web server publik.
443HTTPS — web traffic terenkripsi.▶
Standar production. Selalu pakai HTTPS untuk traffic publik.
💀Bahaya · Common MistakeBuka SSH (22) ke 0.0.0.0/0 = seluruh internet bisa nyoba brute-force login ke server lo. Ini salah satu misconfig paling berbahaya & paling sering. Batasi ke IP kantor/rumah lo saja.
🎯Real Case · Checklist"Nginx udah running di EC2 tapi web nggak bisa dibuka dari browser — cek apa?" Telusuri dari luar ke dalam:
① EC2 punya public IP?
② Instance di public subnet?
③ Route table → Internet Gateway?
④ Security Group allow port 80?
⑤ OS firewall (ufw) di Ubuntu?
⑥ Nginx-nya beneran running?
04

EC2

MCP Verified

Elastic Compute Cloud — server virtual lo. Ini "mesin" yang ngejalanin aplikasi. Service yang paling sering disentuh DevOps pemula.

Konsep Inti

InstanceSatu server virtual yang jalan.▶
Dibuat dari sebuah AMI + instance type. Tiap instance dapat private IP, dan optional public IP.
AMITemplate OS + software awal.▶
Amazon Machine Image — "cetakan" instance, mis. Ubuntu 22.04. Bisa bikin AMI sendiri dari server yang udah dikonfigurasi.
Instance typeUkuran CPU/RAM, mis. t3.micro.▶
Menentukan resource & harga. t-family (burstable) cocok untuk beban ringan/lab.
Key pairKunci SSH (.pem) untuk login.▶
AWS simpan public key, lo pegang private key (.pem). Tanpa file ini, nggak bisa SSH masuk.
User dataScript otomatis saat first boot.▶
Script (bash) yang jalan sekali saat instance pertama nyala — mis. auto-install Nginx. Otomatisasi bootstrap.
Public vs Private IPAlamat dari luar vs dalam.▶
Public IP bisa berubah saat instance di-stop/start. Butuh IP tetap? Pakai Elastic IP. (Ingat: public IPv4 sekarang berbayar — lihat section Billing.)
Stop vs TerminateMatikan sementara vs hapus permanen.▶
Stop = instance dimatikan tapi tidak dihapus; EBS root volume tetap ada (data aman), saat di-start lagi biasanya dapat public IP baru. Terminate = instance dihapus permanen. Data di instance store hilang. (Tervalidasi via AWS Docs.)
ssh-ke-ec2.sh
$ chmod 400 mykey.pem
$ ssh -i mykey.pem ubuntu@PUBLIC_IP
# user default Ubuntu = 'ubuntu'
🎯Real Case"Deploy web app sederhana di EC2 Ubuntu." → Launch instance (AMI Ubuntu, t3.micro), pasang key pair, buka port 80 di Security Group, SSH masuk, install Nginx, taruh aplikasi. Pakai user data kalau mau otomatis.
🧠DevOps MindsetSelalu tag instance (Name, Env, Owner). Tanpa tag, 3 bulan lagi lo bingung "ini server apa, punya siapa, boleh dimatiin nggak?"
05

EBS & AMI

Storage & template untuk EC2. EBS = "hard disk"-nya server. AMI = "cetakan" untuk bikin server kembar.

EBS VolumeBlock storage (disk) yang nempel ke EC2.▶
Elastic Block Store — disk virtual untuk EC2. Root volume menyimpan OS. Datanya persisten (tetap ada walau instance di-stop). Catatan billing: EBS volume tetap kena biaya walau instance dimatikan.
SnapshotBackup point-in-time dari EBS.▶
"Foto" isi volume pada satu waktu, disimpan di S3 (managed). Dipakai untuk backup & restore data disk.
AMITemplate lengkap OS + konfigurasi.▶
Bikin AMI dari server yang sudah dikonfigurasi → bisa launch server identik berkali-kali. Dasar untuk Auto Scaling & replikasi cepat.
🎯Real Case"Sebelum upgrade package besar di server, backup apa dulu?" → Ambil EBS Snapshot dari root volume. Kalau upgrade gagal/rusak, lo bisa restore dari snapshot.
🧠Snapshot vs AMIButuh backup data disk → Snapshot. Butuh cetakan server lengkap untuk diluncurkan ulang (mis. buat ASG) → AMI.
06

Elastic Load Balancing

MCP Verified

"Resepsionis" yang membagi traffic ke banyak server sehat. Wajib untuk aplikasi production yang serius.

Load Balancer (ALB)Pembagi traffic layer HTTP/HTTPS.▶
Application Load Balancer bekerja di layer 7 (HTTP/HTTPS), cocok untuk web app. Menerima request user lalu membagikannya ke target sehat.
Target GroupKumpulan EC2 tujuan traffic.▶
Grup target (mis. EC2) tempat ALB meneruskan request. ALB hanya mengirim ke target yang lolos health check.
Health CheckCek berkala apakah target sehat.▶
ALB rutin "mengetuk" target (protocol/port/path/interval/timeout/threshold bisa diatur). Target harus lolos sejumlah cek berturut-turut untuk dianggap healthy. Penting (tervalidasi): jika semua target unhealthy, ALB "fail open" — meneruskan ke semua target apa adanya.
ListenerPort yang didengarkan ALB (80/443).▶
Aturan: "request masuk di port 443 → teruskan ke target group X". Listener HTTPS butuh sertifikat (mis. dari ACM).
🎯Real Case"Traffic user masuk ke ALB lalu diteruskan ke EC2 yang sehat." → User → ALB (listener 443) → Target Group → EC2 yang lolos health check. Kalau satu EC2 mati, ALB otomatis berhenti mengirim ke situ.
🧠DevOps MindsetDi production, jangan expose EC2 langsung ke internet. Taruh ALB di depan: lebih aman, bisa SSL termination, health check, dan gampang nambah server di belakangnya.
07

Auto Scaling Group

Nambah server saat ramai, ngurangin saat sepi — otomatis. Hemat biaya sekaligus tahan beban.

Launch TemplateResep cara bikin instance baru.▶
Mendefinisikan AMI, instance type, key pair, Security Group, user data. ASG pakai ini untuk meluncurkan instance baru yang seragam.
Min / Desired / MaxBatas jumlah instance.▶
Minimum = jumlah terkecil yang selalu jalan. Desired = target saat ini. Maximum = batas atas. ASG menjaga jumlah instance tetap di antara batas ini.
Scaling PolicyPemicu nambah/ngurangin.▶
Mis. "kalau rata-rata CPU > 70%, tambah instance". Berbasis metric CloudWatch.
Health Check + ELBGanti instance sakit otomatis.▶
ASG sering dipasang dengan ALB: instance baru otomatis didaftarkan ke Target Group, dan instance yang gagal health check diganti otomatis.
🎯Real Case"Kalau traffic naik, server bertambah otomatis." → CloudWatch deteksi CPU tinggi → scaling policy nambah instance → instance baru daftar ke Target Group ALB → traffic kebagi. Saat sepi, instance dikurangi lagi. Lo tidur, AWS yang kerja.
08

S3

MCP Verified

Simple Storage Service — "gudang" object storage tanpa batas. Tempat artifact build, backup, file statis, log. Salah satu service paling sering dipakai.

BucketWadah utama, nama unik global.▶
Container untuk object. Nama bucket harus unik di seluruh AWS dan terikat ke satu Region.
Object & KeyFile + "alamat"-nya di bucket.▶
Object = file-nya. Key = nama/path lengkap object, mis. builds/app-v1.zip. S3 itu flat — "folder" hanyalah prefix pada key.
VersioningSimpan riwayat tiap perubahan object.▶
Aktifkan untuk data penting: kalau file ketimpa/terhapus, versi lama masih bisa dipulihkan.
EncryptionEnkripsi data at-rest.▶
S3 mendukung enkripsi server-side. Aktifkan untuk data sensitif.
Block Public AccessPelindung dari kebocoran publik.▶
Tervalidasi via AWS Docs: aktif secara default untuk semua bucket baru. Biarkan menyala; kalau butuh akses publik (mis. static website), atur lewat bucket policy, bukan ACL.
Static Website HostingSajikan HTML langsung dari S3.▶
S3 bisa hosting website statis (HTML/CSS/JS). Sering dikombinasikan dengan CloudFront untuk HTTPS + CDN.
s3-basic.sh
$ aws s3 ls                                  # list semua bucket
$ aws s3 cp index.html s3://nama-bucket/       # upload artifact
🎯Real Case"Simpan artifact build frontend ke S3." → Pipeline CI/CD build → aws s3 cp dist/ s3://my-artifacts/ --recursive → artifact tersimpan, siap di-deploy/serve.
⚠️Common MistakeBikin bucket public sembarangan (data bocor) · lupa versioning untuk data penting · salah paham S3 seperti folder biasa — padahal flat object store, bukan filesystem.
09

RDS

MCP Verified

Relational Database Service — database (MySQL/PostgreSQL/dll) yang dikelola AWS. Lo nggak ngurus patching, backup, replikasi manual.

Managed DBAWS urus backup, patch, scaling.▶
Lo fokus ke schema & query; AWS urus operasional infrastruktur DB. Hemat waktu besar dibanding install DB manual di EC2.
EngineMySQL, PostgreSQL, dll.▶
Pilih engine sesuai aplikasi. Contoh paling umum untuk pemula: MySQL atau PostgreSQL.
DB Instance & StorageServer DB + ukuran disk.▶
Mirip instance type EC2 tapi untuk DB. Storage bisa diatur & (umumnya) di-autoscale.
BackupAutomated backup & snapshot.▶
RDS bisa backup otomatis terjadwal + snapshot manual untuk restore point-in-time.
Multi-AZReplika standby untuk high availability.▶
Tervalidasi: butuh DB subnet group mencakup ≥2 subnet di Availability Zone berbeda. Kalau AZ utama down, RDS failover ke standby. (Multi-AZ DB cluster = 1 writer + 2 reader di 3 AZ, untuk MySQL/PostgreSQL.)
Security Group DBSiapa boleh konek ke DB.▶
Batasi inbound DB (mis. port 3306/5432) hanya dari Security Group EC2 aplikasi, bukan dari internet.
🎯Real Case"Web app di EC2 connect ke RDS di private subnet." → RDS ditaruh di private subnet (tak terjangkau internet). Security Group RDS hanya mengizinkan inbound dari Security Group EC2. Aman & rapi.
⚠️Common MistakeBikin RDS publicly accessible + Security Group buka ke 0.0.0.0/0. Database harus di private subnet, akses dibatasi ketat.

Lambda

MCP Verified

Jalankan kode tanpa ngurus server. Bayar cuma saat kode jalan. Cocok untuk tugas kecil yang event-driven.

Serverless FunctionKode jalan tanpa kelola server.▶
Lo upload fungsi, AWS yang sediakan & skala infrastrukturnya. Nggak ada EC2 yang harus lo patch.
Event-drivenDipicu oleh event (event source).▶
Lambda dijalankan saat ada event — mis. object masuk S3, request API Gateway, atau jadwal terjadwal.
RuntimeBahasa: Python, Node.js, dll.▶
Lingkungan eksekusi kode lo (mis. Python 3.x, Node.js).
HandlerFungsi entry-point yang dipanggil.▶
Tervalidasi: handler adalah method entry-point yang dipanggil Lambda saat invoke. Menerima event (payload) & context (metadata invocation).
IAM Role (Execution)Izin Lambda mengakses service lain.▶
Lambda butuh execution role untuk akses S3, DynamoDB, dll — dan untuk menulis log ke CloudWatch. Terapkan least privilege.
CloudWatch LogsTempat output/log Lambda.▶
Semua print/log Lambda otomatis masuk ke CloudWatch Logs — tempat pertama buat debug fungsi yang error.
🎯Real Case"Lambda jalan saat object masuk S3." → Upload gambar ke bucket → S3 memicu event → Lambda jalan (mis. bikin thumbnail) → log hasilnya ke CloudWatch. Nggak ada server yang nyala 24/7.
🧠Kapan pakaiLambda pas untuk tugas singkat & event-driven (resize gambar, proses webhook). Bukan untuk aplikasi yang jalan terus-menerus & berat — itu ranah EC2/container.

CloudWatch

MCP Verified

"CCTV + logbook" AWS lo. Tempat ngumpulin metrics, logs, dan bikin alarm. Mata lo terhadap kesehatan sistem.

MetricsAngka performa dari waktu ke waktu.▶
Data numerik seperti CPU EC2, koneksi RDS, durasi Lambda. Bisa di-grafik & jadi dasar alarm.
LogsCatatan teks dari aplikasi/service.▶
CloudWatch Logs mengumpulkan log dari Lambda, EC2 (via agent), dll untuk dicari & dianalisis.
Log Group & Log StreamFolder log & aliran log per sumber.▶
Log Group = wadah log untuk satu aplikasi/fungsi (mis. /aws/lambda/my-fn). Log Stream = aliran log dari satu sumber/instance di dalam group.
AlarmsPicu aksi saat metric lewati ambang.▶
Tervalidasi: alarm bisa berbasis metric atau metric filter dari log. Saat state berubah, alarm bisa memicu notifikasi (SNS) atau aksi Auto Scaling/EC2/Lambda.
DashboardPanel visual gabungan metric.▶
Kumpulkan grafik penting di satu layar untuk pantauan cepat.
🎯Real Case"CPU EC2 tinggi → alarm kirim notifikasi." → Buat CloudWatch Alarm pada metric CPUUtilization > 80% selama X menit → saat terpicu, kirim notifikasi (lewat SNS — cukup tahu konsepnya dulu, detail SNS adalah next step).
🧠DevOps MindsetAplikasi tanpa monitoring = nyetir malam tanpa lampu. Pasang alarm untuk metric kritikal (CPU, disk, error rate) sebelum masalah jadi insiden.

Route 53 & DNS

MCP Verified

DNS managed AWS — "buku alamat" yang menerjemahkan nama domain jadi alamat resource. Bikin app.domain.com nunjuk ke server lo.

Hosted ZoneWadah record DNS untuk satu domain.▶
Kontainer semua DNS record milik domain lo (mis. domain.com).
A RecordDomain → alamat IPv4.▶
Memetakan nama ke IP, mis. app.domain.com → 13.250.x.x.
CNAMEDomain → domain lain.▶
Alias ke nama domain lain. Tidak bisa dipakai di zone apex (root domain domain.com).
Alias RecordDomain → resource AWS (ALB, S3, CloudFront).▶
Tervalidasi: ekstensi khusus Route 53. Bisa dipakai di zone apex (beda dari CNAME), otomatis mengikuti perubahan IP resource target, dan memakai TTL default resource tersebut. Ini cara tepat mengarahkan domain ke ALB/CloudFront.
TTLBerapa lama record di-cache.▶
Time To Live — makin kecil, perubahan makin cepat tersebar, tapi query lebih sering. (Alias mengikuti TTL target.)
🎯Real Case"app.domain.com diarahkan ke ALB." → Buat Alias record di Hosted Zone yang menunjuk ke DNS Load Balancer. Pakai Alias (bukan CNAME) supaya bisa di root domain & otomatis ikut kalau IP ALB berubah.

CloudFront

SINGKAT

CDN AWS — cache konten di lokasi dekat user biar cepat. Cukup paham konsepnya dulu.

CDNJaringan distribusi konten global.▶
Content Delivery Network — menyajikan konten dari server terdekat dengan user, mengurangi latency.
Edge LocationTitik cache di banyak kota dunia.▶
User di Jakarta dilayani dari edge terdekat, bukan harus ke server origin yang jauh.
OriginSumber asli konten.▶
Tempat konten asli berada — sering S3 (file statis) atau ALB/EC2 (aplikasi).
CacheSalinan konten di edge.▶
Konten yang sering diakses disimpan di edge agar request berikutnya super cepat tanpa hit origin.
🎯Use Case · S3 + CloudFront + HTTPSPola umum: file statis (HTML/JS/gambar) di S3, dipasang CloudFront di depannya untuk cache global + HTTPS. Hasilnya: website statis cepat, aman, murah, dan tahan traffic besar.

AWS CLI

MCP Verified

Kendalikan AWS dari terminal — fondasi otomatisasi & scripting. Wajib dikuasai DevOps.

aws configureSetup access key, region, output.▶
Mengisi Access Key ID, Secret Access Key, default region (mis. ap-southeast-1), dan output format (json/table/text). Disimpan di ~/.aws/credentials & ~/.aws/config.
sts get-caller-identity"Aku login sebagai siapa?"▶
Tervalidasi: mengembalikan Account ID, ARN, & User ID dari credential yang dipakai. Tidak butuh permission khusus. Command pertama untuk memastikan lo terhubung ke akun/identity yang benar.
region & outputKonteks default tiap command.▶
Banyak resource bersifat per-Region. Salah region = "resource nggak ketemu" padahal ada di region lain.

Command Wajib

aws-cli-basic.sh
$ aws configure                 # isi key, region, output
$ aws sts get-caller-identity   # cek lo login sebagai siapa
$ aws s3 ls                      # list bucket S3
$ aws ec2 describe-instances    # lihat instance EC2
💀Warning KeamananJangan share Access Key. Jangan commit credentials ke GitHub — bot scanning bisa nemu & pakai dalam hitungan menit (bisa kena tagihan ribuan dolar). Pakai .gitignore, environment, atau IAM role. Kalau key bocor, langsung rotate/disable.
⚡Mini PracticeCoba di terminal simulator di bawah → ketik aws sts get-caller-identity, lalu aws s3 ls dan aws ec2 describe-instances. Ketik help untuk daftar command.

Billing & Cost Awareness

MCP Verified

Skill DevOps yang sering dilupakan: jangan sampai lab belajar bikin tagihan kaget. Free Tier ada batasnya.

💸Yang Sering Bikin Tagihan
• Free Tier ≠ semuanya gratis — ada batas jam/kapasitas & periode 12 bulan.
• EC2 running = kena biaya selama nyala (matikan kalau nggak dipakai).
• EBS volume tetap dibayar walau instance di-stop.
• NAT Gateway kena biaya per jam + per GB — bisa terasa mahal untuk pemula.
• Load Balancer kena biaya selama aktif.
• Public IPv4 — tervalidasi via AWS Docs: sejak 1 Feb 2024 AWS mengenakan biaya per jam untuk public IPv4 (ada kuota Free Tier 750 jam/bulan selama 12 bulan untuk IP yang terpakai di EC2). Karena harga bisa berubah, selalu cek AWS Pricing / Billing Dashboard terkini.

Pakai Pengaman Biaya

Set AWS Budgets + Billing Alarm agar dapat notifikasi saat biaya mendekati batas. Ini wajib sebelum mulai ngelab.

Mini Project End-to-End

"Deploy Simple Web App di AWS Core Services" — gabungkan semua yang dipelajari jadi satu arsitektur nyata.

Arsitektur TargetUser → Route 53 → ALB → EC2 (Ubuntu/Nginx) → RDS (optional). Static asset optional di S3, monitoring di CloudWatch.
1
Siapkan VPC
Untuk lab pemula, boleh pakai default VPC dulu — nggak perlu bikin dari nol.
2
Launch EC2 Ubuntu
AMI Ubuntu · t3.micro · pasang key pair
3
Install Nginx di EC2
sudo apt update && sudo apt install nginx -y
4
Buka port 80 di Security Group
Inbound HTTP (80) dari 0.0.0.0/0 · SSH (22) dibatasi ke IP lo.
5
Test via public IP
http://<public-ip>
6
Buat Load Balancer (ALB)
Listener HTTP 80 → Target Group.
7
Attach EC2 ke Target Group
Pastikan health check healthy.
8
Test via DNS Load Balancer
http://<alb-dns-name>
9
Setup CloudWatch alarm (konsep)
Alarm CPU EC2 tinggi → notifikasi.
10
Arahkan domain via Route 53 (optional)
Alias record → DNS ALB.
11
Cleanup semua resource
Ikuti checklist di section Billing. Wajib.
⚠️Catatan BiayaUntuk lab pemula, hindari NAT Gateway dan RDS dulu jika belum siap dengan biayanya. Fokus ke EC2 + ALB + Nginx; RDS & domain bisa menyusul.

Troubleshooting Flow

"Website nggak bisa diakses!" — telusuri dari DNS sampai disk. Disiplin urutan = nemu masalah lebih cepat.

1
DNS sudah benar?
Domain resolve ke ALB/IP yang tepat? Cek record Route 53.
2
ALB healthy?
Listener aktif, ALB state normal?
3
Target Group healthy?
Target lolos health check? Kalau semua unhealthy, ALB "fail open".
4
EC2 running?
Instance state = running, bukan stopped.
5
Security Group allow 80/443?
Inbound rule mengizinkan port web?
6
Nginx running?
sudo systemctl status nginx
7
Ada error di app log?
sudo tail -f /var/log/nginx/error.log
8
Disk penuh?
df -h
9
Cek CloudWatch metrics/logs
CPU spike? Error rate naik? Log error apa?

MCP Verified Notes & References

MCP Verified

Materi ini disusun berdasarkan AWS Documentation yang divalidasi via AWS MCP Server pada saat pembuatan. Berikut fakta-fakta kunci yang dikonfirmasi langsung dari dokumentasi resmi.

Fakta yang Divalidasi via MCP

IAM — Root userBest practice: root jarang dipakai, amankan dgn MFA, tanpa access key; gunakan identity/role least-privilege untuk daily work.
Security Group vs NACLSG = level instance, stateful, allow-only. NACL = level subnet, stateless, allow+deny, perlu atur return traffic eksplisit.
S3 Block Public AccessAktif secara default untuk semua bucket baru; jika butuh akses publik gunakan bucket policy, bukan ACL.
RDS Multi-AZButuh DB subnet group ≥2 subnet di AZ berbeda; Multi-AZ DB cluster = 1 writer + 2 reader di 3 AZ (MySQL/PostgreSQL).
ALB Health CheckHanya kirim traffic ke target sehat; jika SEMUA target unhealthy, ALB "fail open" ke semua target.
Route 53 Alias vs CNAMEAlias bisa di zone apex & ikuti perubahan IP resource AWS; CNAME tidak bisa di zone apex.
EC2 Stop vs TerminateStop = instance dimatikan, EBS root tetap ada, restart umumnya dapat public IP baru. Terminate = dihapus permanen.
Lambda HandlerHandler = method entry-point yang dipanggil saat invoke; menerima event (payload) + context (metadata).
CloudWatch AlarmAlarm berbasis metric / metric filter dari log; saat terpicu bisa kirim notifikasi (SNS) atau aksi Auto Scaling/EC2/Lambda.
AWS CLI Identityaws sts get-caller-identity mengembalikan Account ID, ARN, User ID; tidak butuh permission khusus.
Public IPv4 ChargeSejak 1 Feb 2024, public IPv4 berbayar per jam; Free Tier 750 jam/bulan (12 bulan) untuk IP terpakai di EC2. Cek pricing terkini.
NAT Gateway CostKena biaya provisioning per jam + per GB data diproses — bisa mahal untuk lab pemula.
